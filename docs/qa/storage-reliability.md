# 大容量存档与故障恢复验收

## 存储规则

游戏使用 IndexedDB 保存自动槽、三个手动槽、上一份有效备份、岁首快照、导入前进度及测试版回退数据。正式版与测试版使用独立的键。首次打开会在事务中复制旧版 LocalStorage 数据；数据库已有记录时不使用旧副本覆盖，旧副本本身也不删除。不支持 IndexedDB 的环境保留原来的同步兼容路径；数据库打开失败时不会把旧副本冒充最新进度，会显示重试提示。

行动仍同步结算，但写入状态分为“正在写入”“确认保存”“未写入”。内存中的待写状态不会冒充已持久化状态；关闭页面时尚有写入或故障会请求浏览器提示。备份和进度在同一事务中提交，异常会整体撤销写入。数据库事务也会比较写入前的内容，阻止两个标签页先后用旧数据覆盖新进度。写入失败时保留当前游玩进度，显示下载备份入口；重试会保存当前完整世界。

导入支持最大 64 MB 的 JSON 文件，下载不再受旧版 8 MB 上限限制。人物纪事、关系和未完剧情没有为缩小存档而裁剪。下载文件与导入前回退均保留。演示图鉴使用独立的临时内存，不打开玩家数据库。

## 回归方法

```sh
npm ci
node --test tests/*.test.cjs
node tests/palace-flow.cjs
node tests/family-garden-browser-fixtures.cjs
NODE_PATH=/path/to/playwright/node_modules node tests/storage-browser-acceptance.cjs
```

数据库事务测试使用 fake-indexeddb；浏览器测试使用真正的 Chrome IndexedDB。浏览器测试仅在隔离的临时浏览器环境中布置旧档与容量故障，游戏操作通过实际按钮、文件导入完成；不读取玩家真实存档。

| 场景 | 验证内容 |
| --- | --- |
| 旧存储写满 | 填满 LocalStorage 直到抛出 QuotaExceededError，自动接续旧档，保存三个手动槽，连续三次转月、刷新读取，核对原始副本未变 |
| 大文件 | 导入 12,010,166 字节的合成容量测试档，保存手动槽、刷新恢复、下载并逐字比较大字段，回退导入前进度，再读取大档 |
| 写入失败 | 在数据库写入边界注入 QuotaExceededError，确认旧档逐字不变、界面不显示成功；解除故障后用“立即保存”写入并刷新 |
| 多标签页 | 两页先读取同一进度，一页推进并保存，另一页尝试覆盖被拒绝，第三页核对胜出的持久化记录 |
| 测试版隔离 | 测试版转月与刷新不改变正式版记录 |
| 公开演示隔离 | 打开关系演示页面，确认不创建或连接玩家存档数据库 |

另有单元回归覆盖迁移事务失败、数据库打不开、连续写入排队、损坏主档使用备份、真正的月末未完事件重建、保存失败后重试、导入回退以及旧版不支持数据库的路径。

## 本地结果

2029 项自动测试全部通过，60 个月完整流程通过。桌面 1440×1000 与手机 390×844 共 12 个存储场景通过，累计 14 次刷新恢复：[本地存储报告](storage-local-browser-results.json)。原家庭、选秀与慈宁宫浏览器验收共 26 个场景也全部通过，累计 80 次刷新恢复。

测试复现了旧存储达到容量上限的故障，没有取得玩家报告问题时的原始档案。真实设备磁盘耗尽、浏览器禁止本站存储、清除站点数据等仍需按界面提示处理；这些情况不会被承诺为无限可保存。
