# 人生与亲缘验收

日期：2026-11-15。测试加载 `index.html` 中实际使用的游戏模块。README 展示玩法；本页保留验证范围与限制。

## 验收目标

| 方向 | 可观察的结果 | 验证 |
|---|---|---|
| 经历影响打算 | 旧作接续编；有过分离的母亲提出指定孩子的亲子手记 | 九种兴趣、实际过继身份、再次有孕、探视关闭与恢复 |
| 亲近与信任分开 | 接受礼物仍保留具体心结，道歉后需跨月兑现意愿 | 同月刷好感不解结，新伤不继承旧道歉，换朝不继承皇帝承诺 |
| 选择因人而异 | 私藏、公开与合编有不同用途；作者与合作者可能意见不同 | 公开作品被实际读者使用；未经征询公开私稿留下负面记忆与合作保留 |
| 人物自行往来 | 固定合作者轮流相助，并影响后续搭档选择 | 每月上限、八个月间隔、缺席暂停、死亡终止、具体姓名不替换 |
| 温暖的长期回响 | 年度闲约、旧物赠予、成年后使用、继位携带 | 错过无惩罚，重复赴约不重复结算；不向已故母亲编造新对话 |
| 可复盘的纪事 | 按事实归为篇章，可看原文与参与人；主观记忆另列 | 展示不改状态、不抽随机数、转义文本、原始时间线保留 |

## 游玩反馈对应的回归

- **生产后血崩去世**：生母本人有结构化生产结局，写出孩子及死亡原因；孩子也记下生母因血崩去世。已故档案固定显示「终事 · 生产与离世」。单胎、双胎、三胎、死胎、产妇存活、待赐名重启、重复结算均覆盖。
- **旧档补记**：仅在存档明确保存「生产已结算、难产、生母已故」时补记，优先沿用原纪事、起居注或出生记录的日期。已有短记录原位补全；不凭体弱性格或已故状态猜死因。
- **太后母家姨母请养**：覆盖真实 `dowagerProposal` 荐入的堂妹，以及既有亲姐妹、堂姐妹。不再依赖 `kinArrival` 标记。生母生产去世后优先接单个请养场景，同胎一起处理。年轻、有孕、已有孩子、生母位分高和储君身份均不单独排除亲缘照护；已有合适养母、人物离宫等约束仍生效。
- **暂缓与旧档接续**：请求暂缓可从姨母档案继续；不会每月重复弹同一请求。旧档的失母孩子可在下次月末接上已有姨母的请求。本人纪事、孩子与已故生母的客观纪事都保留结果，原生母身份不变。
- **妃子宫殿入口**：档案可进入实际居处，迁宫后更新；前往本身不扣精力，抵达后的互动按原规则执行。冷宫、离宫与已故角色不提供普通入宫入口。
- **姓名字库**：运行时字库不含「晟」「蓓」，已有存档姓名不强制改写。

## 自动化结果

合并主分支的娘家亲属功能后，完整回归 **702 项通过**，60 个月流程验证通过。合并前的人生与亲缘功能回归为 677 项。合并后另以 `lives`、`relationships` 策略及种子 202 各跑 60 个月，共 649 次选择，没有运行错误。

完整测试命令：`node --test tests/*.test.cjs`。使用 Node 22。流程命令：`node tests/palace-flow.cjs`，检查 60 个月以及页面、家事、宴会与存读档。

专项文件：`palace-personal-life.test.cjs`、`palace-birth-chronicles.test.cjs`、`palace-aunt-care.test.cjs`。其中包含新运行环境恢复未处理选择、结果页不重复结算，以及继承人真实登基后保留原作者署名的检查。

运行了 12 局混合策略与 4 局改变作品选择的专项策略，合计 **2,554 个月、13,592 次选择**；没有运行错误，未检测到性格或小性子被事件意外改写。每局至多 180 个月，部分因正常结局提前结束，不能视为 16 局全部活到十五年。

后四局随机尝试私藏、公开、合编与暂缓，实际出现合编后的轮流相助。脚本按原始事件和人物纪事采样；「改日再谈」等未改变世界的回应不要求编造已完成的纪事。后四局中，排除无状态变化的暂缓回应后，347 次新增内容的实际决定均有当事人纪事。其余旧事件的自动漏记候选包含导航、背景人物和尚待下一步结算，需要逐条解释，不能将候选数等同于 bug 数。

数据见 [逐局统计](personal-life-matches.json) 与 [人物连续经历样本](personal-life-traces.json)。成年回响与跨代继承主要由定向回归覆盖；这些自然局中的孩子尚未实际触发成年旧物回响，不把定向设定混称为随机遇到。

## 浏览器实机

使用 `tests/personal-life-browser-fixture.cjs` 生成本地中期演示页，通过真实操作验收；演示页面不发布。演示存档明确设置了生产死亡分支，以复现用户报告，截图不是自然触发概率的证据。

1. 打开沈知微的续编计划，看到固定合作者柳音及两人不同的传阅意愿；刷新并读取自动存档，仍恢复同一场景。
2. 按原商定留稿，双方作品和纪事落盘；人生篇章可展开最初计划到完成的原始记录。
3. 390 × 844 手机视口检查，页面宽度与滚动宽度均为 390，没有横向溢出；作品与相赠按钮可用。
4. 点妃子「去宫里看看」，进入景仁宫，显示该妃子的迎驾与宫中近况；前往前后精力一致。
5. 给体弱的柳清和所生孩子赐名清宁，结算血崩；接着出现太后母家的柳清音请求照料。刷新后仍能恢复请养，允准后孩子生母保留、养母改为柳清音。
6. 从「故人」打开柳清和，固定死亡栏与本人纪事明确写出临盆、清宁出生、产后血崩薨逝，以及后续姨母请养结果。
