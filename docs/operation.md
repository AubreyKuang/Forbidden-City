## TapTap：为什么不能上架

### 1. 题材被拒

预约版（V-20261126）的审核结论：

> 游戏题材涉及【古代帝王 / 朝廷政治治理】问题，暂不符合收录要求。

宸宫纪的核心玩法就是当皇帝、批奏折、治理朝政，换个包装也绕不开，所以这一条基本无解。目前先放一放，不再提审。

### 2. 版号

即使题材过了，还有版号这道坎：

- 后台规则：游戏含「文字剧情模拟」内容就需要版号，测试和上线都要，只有「预约」阶段不需要。宸宫纪属于这一类。
- 这条规则在公开文档里没有写明，以开发者后台为准。
- 已经提工单问过 TapTap：免费、单机、文字剧情模拟类的 H5 能否不要版号开放试玩。还没有答复。

### 后台现状

- 厂商：允佩工作室（个人主体，已认证）。
- 游戏 ID 1099762，H5 包体、商店素材、隐私政策、适龄 16+、AI 声明都已填好，见 [taptap/README.md](taptap/README.md)。
- 认证时后台自动生成的空草稿（1088658）没有包体类型，传不了 H5，不用管。
- TapTap 开发者协议是非独占的，同一款游戏可以同时放在小红书、网页等其他平台。只有「TapTap 制造」项目要求独占。

### 以后想重新尝试

1. 先看工单答复，确认文字剧情模拟类 H5 是否必须有版号。
2. 题材问题需要在后台提工单申诉，或者等平台政策变化。没有明确松口之前，不建议改题材硬上。

## 小红书小工具

### 免费版规则

小红书版和网页版用同一份源码，差异全部写在 `scripts/xhs-edition.json`，只在打包时生效：

| 项目 | 小红书免费版 | 配置字段 |
| --- | --- | --- |
| 剧情妃 | 只开放阿依慕（第一年中秋宫宴就会遇到），其余显示「敬请期待」 | `allow.story` |
| 风华人物 | 只开放上官兰台（开局就能在御书房遇到） | `allow.fenghua` |
| 皇帝代数 | 最多三代，第三代退位或驾崩时显示「试玩到此为止」和三朝本纪 | `maxGenerations` |
| 手动存档 | 3 个（和网页版相同） | — |
| 换立绘 | 不能。包里不含 `dev.html` 和金手指，出现就构建失败 | — |
| 存档导出、浏览器存储 | 关闭，只用小红书容器存储 | `features` |

特殊剧情（穿越、仙缘、前世）、锦衣卫全部案件、微服私访都不限制。开局「选择帝王画像」保留。

想多放开一位人物，就在 `allow` 里加上她的 id，重新打包。

### 打包

**一次性准备：** 在仓库外建一个工具目录，装打包用的转译工具。这些工具不会进包。

```bash
mkdir -p ~/xhs-tools && cd ~/xhs-tools && npm init -y >/dev/null && npm install esbuild@0.24.2 lightningcss@1.28.2 acorn@8.14.0 sharp@0.33.5
```

**打包：** 在仓库根目录运行。产物是 `dist/xhs/chengongji-xhs-V<版本号>.zip`，展开目录是 `dist/xhs/package/`。

```bash
python3 scripts/build-xhs.py --tools ~/xhs-tools --version 1.0.1
```

构建过程中会自动做这些事，任何一项不通过都会直接失败：

- 改写 `index.html`：只引用外部 defer 脚本，JS 加载前就能看到「宸宫纪 / 正在准备…」首屏。
- JS 转译到 ES2017 / Chrome 61，CSS 降到 Chrome 61 基线。
- 579 处行内事件（`onclick` 等）改成 `data-on*`，由 `js/inline-actions.js` 统一处理，不用 eval。
- 202 个脚本按原顺序拼成 `js/app-1.js`、`js/app-2.js`（每个都在 2 MiB 以内）。拼接前会检查文件开头的 `"use strict"`、重复的顶层声明、加载时引用后面文件的名字、`document.currentScript`。
- 图片只打包游戏会用到的，锁定人物的立绘不打包，全部缩到显示尺寸的 2 倍并转成 WebP。
- 扫描禁用能力：行内脚本和事件、eval、`new Function`、WASM、iframe、fetch/XHR、`window.open`、`prompt`、外链、下载链接等。
- 包内不能出现金手指、测试模式文件。
- 文件数超过 200 失败，超过 150 警告。

**检查：** 打包后再跑这几项。

```bash
node --test tests/*.test.cjs
node scripts/xhs-browser-check.cjs xhs
```

- 第二条要 Node 22+ 和 Google Chrome。它会在严格 CSP（`script-src 'self'`）下，用模拟的小红书容器点一遍游戏，检查报错、CSP 违规、缺失文件、浏览器存储访问，以及存档能否读回。
- 再用小红书官方 skill 的审计脚本检查目录和 zip。skill 下载地址见创作服务平台上传页「第一步」，解压到 `.claude/skills/minitool-zip-builder/`（已在 `.git/info/exclude` 里，不提交）：

```bash
python3 .claude/skills/minitool-zip-builder/scripts/audit_artifact.py dist/xhs/chengongji-xhs-V1.0.0.zip
```

正常结果是 PASS，只有一条「zip 超过建议的 2 MiB」的 WARN。超出主要是因为 44 张立绘图集，再压人脸会糊，可以接受。

### 平台限制（踩过的坑）

| 限制 | 说明 |
| --- | --- |
| zip ≤ 10 MB | 硬性上限。当前 8.27 MiB |
| 文件数 ≤ 200 | 硬性上限，官方审计脚本**不检查**，上传部署时才报错。V1.0.0 第一次就是因为 324 个文件被拒 |
| 只能有外部脚本 | 容器 CSP 禁止行内 `<script>` 和 `onclick=""` |
| 存储 | 只能用 `window.xhs.miniTool.setStorage/getStorage`，单 key 1 MB，总共 10 MB，客户端 9.46.0 起；不能回退到 localStorage / IndexedDB |
| 胶囊按钮 | 右上角胶囊会挡内容，用 `getWindowInfo` 拿位置后避让 |

存档的做法：按 1M 字符分段，LZW 压缩后存，每个 key 不超过 900 KiB；新存档写完才替换旧的。三个手动存档位都存到第三代末期，加上自动存档，最坏约 7.6 MB，仍在 10 MB 以内。

### 上传和发布

入口：<https://creator.xiaohongshu.com/new/red-app>（创作服务平台 → Builder hub → 小工具 → 上传小工具）。

1. **第二步**上传 zip，等「部署成功」。部署时会依次显示安全检测、构建、验证运行状态，大约半分钟。如果提示「CORS blocked or network error」，重新上传一次即可。
2. 填表：

   | 字段 | 填写 |
   | --- | --- |
   | 版本号 | 语义化版本，如 1.0.0；每次更新要比上次大 |
   | 所需权限 | 不需要权限 |
   | 小工具名称 | 宸宫纪 |
   | 简介 | 当一回皇帝，批折子选秀（≤14 字） |
   | 图标 | `docs/xhs/icon-1024.jpg`（1:1，≤5 MB），上传后要点「确认裁剪并上传」 |
   | 封面 | `docs/xhs/cover-1080x1440.jpg`（3:4，≤10 MB），上传后点「确定」 |
   | 场景标签 | 休闲玩法 |

   封面是从 `assets/images/palace-painted-cover.webp` 左侧裁出的 3:4（书法标题加红色宫门），图标是 `docs/taptap/icon-1024.png` 转成的 JPG。1.5 MB 的 PNG 图标裁剪上传时失败过，改用 JPG 就好了。
3. 部署成功后，右侧会出现「手机扫码预览」二维码，用小红书 App 扫码，在真机上试玩。发布前只有自己能看到。
4. 勾选《小工具发布安全规范》（链接打开是《小工具服务协议》），点「发布小工具」，进入审核。审核中可以「撤回」。
5. 审核通过后，发笔记时在「发布页 → 添加组件 → 小工具」里挂载。

**注意：** Claude 桌面端内置浏览器不能往网页里放本地文件，上传要在已登录小红书的 Chrome 里做。

### 易次元版和网页版的区别

- **内容：** 完整版，所有人物都开放，皇帝代数不限。配置在 `scripts/yiciyuan-edition.json`。
- **存档：** 存到易次元账号的云端（SDK 的 profile 接口），换手机登录同一账号也能读。每个存档位占一个云存档位置：自动存档 0，存档 1/2/3 是 3、5、7，49 用来开机检测。上传期间攒下的多次存档会合并成一次上传。云存档打不开时（没登录、断网），会提示「当前无法存档」，可以不存档先玩。
- **登录与游玩时长：** 打开时 SDK 自动登录；开新局或读档时上报一次 `logGamePlay`。
- **退出：** 用平台自带的左上角退出按钮，顶栏左边留出 52px。
- **纪念卡：** WebView 不能下载文件，起居注纪念卡改为全屏显示，长按图片保存。
- 测试模式、金手指、存档导出都不在包里。

### 商城（内购）

易次元版的游戏里有「商城」页面（底部导航，「存档」前面）。商品在万象笺后台「进阶配置 → 配置商品」建好，商品 ID 写在 `scripts/yiciyuan-edition.json` 的 `shop.products` 里：

| 商品 | 商品 ID | 价格 | 购买次数 | 效果 |
| --- | --- | --- | --- | --- |
| 银两小包 | 2485888261127001 | 60 次元币（6 元） | 可重复 | 当前这一朝国库 +500 万两 |
| 银两大包 | 2485888261127002 | 200 次元币（20 元） | 可重复 | 当前这一朝国库 +2000 万两 |
| 画师换像 | 2485888261127003 | 99 次元币（9.9 元） | 一次 | 普通妃嫔详情页出现「更换立绘」，从图库里挑；剧情人物不能换 |
| 传说珠翠立绘包 | 2485888261127004 | 30 次元币（3 元） | 一次 | 传说名妃 24 张 + 珠翠 6 张：没买时不出现在新秀女里、也不能选；买后都可以 |
| 金手指包 | 2485888261128001 | 198 次元币（19.8 元） | 一次 | 商城顶部出现「立即召见」：本朝还没相遇的剧情妃和风华人物，点名字马上进入她/他的初遇剧情，不受时间、地点、前置条件限制，不耗精力；含画师换像和传说珠翠立绘包 |

华服、古风盛装等其他立绘都在普通立绘池里，不收费。

规则（`js/palace-shop.js`）：
- 点「购买」后要再点「确认支付」才会调用平台扣费；平台自己不弹窗。
- 银两：平台的已购次数减去已到账次数（存在账号变量 `paid_<商品 key>`），差额发到当前打开的这一朝。购买后、打开商城、开新局、读档时都会对一遍，所以付了款但页面关掉的也会补到账。
- 一次性商品：每次打开都按平台的已购次数判断，换设备也有效。
- 立绘包的归属写进存档世界（`S.flags.portraitPacks`），只在没有进行中事件时写，保证未完事件重放时用的是同一个立绘池。
- 金手指包（`kind: bundle`）：买了就同时拥有 `includes` 里的商品；归属写进存档（`S.flags.goldFinger`），规则同立绘包。「立即召见」（`A.goldSummon`）进动作日志，召见后没答完就关掉，重开读档还能接着答。服丧期间不能召见。
- 新加商品：后台建商品 → 在 `shop.products` 里加一行（`kind`：`silver` / `painter` / `portraitPack` / `bundle`）→ 重新打包上传。新的立绘包还要在 `PORTRAIT_PACKS` 里写上包含哪些立绘格。

## 收费

- 小红书《小工具服务协议》：一个小工具免费还是付费，选定后不能切换；付费小工具不能下架，只能停售；用户要满 18 岁。
- 目前创作服务平台网页后台上看不到付费选项。
- 计划：先用免费版推广，以后打开「赞赏」（目前内测）；完整版另做一个付费小工具「宸宫纪·全本」。
- 做付费完整版之前要处理一件事：GitHub Pages 上的网页版是完整内容，测试模式 `dev.html`（金手指，可以随意换立绘、改数值）也是公开的，README 里还有链接。到时候要决定网页版是否下线测试模式，或者一起做限制。
